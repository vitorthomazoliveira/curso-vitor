Por que versionar?

        
O fim do “final_v2_revisado_agora_sim”

        
Quem já perdeu um trabalho por sobrescrever um arquivo sabe como isso dói. O controle de versão existe para resolver isso.


        

          

            
Sem versionamento

            
    
              
  • Perda irreversível de código
    • 
              
  • Extrema dificuldade de colaborar em equipe
    • 
              
  • Infinitas pastas e arquivos duplicados
    • 
            

            

              trabalho.docxtrabalho_final.docxtrabalho_final2.docxtrabalho_final_REVISADO.docxtrabalho_final_agora_vai.docx
            

          

          

            
Com controle de versão

            
    
              
  • Cada alteração é rastreada meticulosamente
    • 
              
  • Reversões seguras para qualquer ponto do histórico
    • 
              
  • Trabalho simultâneo e eficiente
    • 
            

            

              
a1f3c9e Adiciona tela de login

              
7be21d0 Corrige cálculo da média

              
3c90aa4 Primeiro commit

Conectando local e remoto

          
Sincronização em nuvem

          
Depois de configurar o projeto localmente, o próximo passo é conectá-lo a um repositório remoto. Essa arquitetura distribuída garante backup seguro na nuvem e permite que várias pessoas trabalhem, revisem e colaborem na mesma base de código, de qualquer lugar do mundo.

        

        
    
          
  • git remote add origin <url>Conecta o repositório local a um servidor remoto (como o GitHub).
    • 
          
  • git pushEnvia seus commits locais para o servidor remoto, atualizando o projeto online.
    • 
          
  • git pullBusca e baixa as atualizações mais recentes do servidor para a sua máquina.
    • 
          
  • git clone <url>Baixa uma cópia completa de um projeto já existente na nuvem.
